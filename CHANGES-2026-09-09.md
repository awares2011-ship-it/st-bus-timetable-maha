# Session changes — 2026-09-09

Focused on the six MSRTC divisional PDFs the user handed over
(Mumbai · Pune · Nashik · Nagpur · Chh. Sambhajinagar · Amravati) and on
the UI overhaul.

## What ships now

### Data — real MSRTC 2025 timetable, no more demo trips
- New pipeline source `msrtc-pdf` (`scraper/sources/msrtc-pdf-source.ts`),
  registered as the default. Reads hand-verified fixtures from
  `data/msrtc/source/manual/` and OCR-derived fixtures from
  `data/msrtc/source/ocr/`.
- **Three hand-verified 2025 fixtures** transcribed directly from the
  PDFs the user provided (with source date + page reference in the JSON
  header, `verified: true` in the generated dataset):
    - `10-pune-shivajinagar-depot-2025-03-11.json` — 130 trips, 48
      destinations from the Shivajinagar bus stand.
    - `20-mumbai-bus-stand-2025.json` — 40 rows from the Mumbai
      Central bus stand page 1 (Tarapur, Alibag, Karad-Satara,
      Bangalore, Kolhapur, Karmala, Nashik CBS, …).
    - `30-nagpur-kondhali-depot-2025-03-12.json` — 139 trips from the
      Kondhali depot page (Akola, Buldhana, Paratwada, Wardha,
      Chandurbazar, Katol, Savner, Arwi, …).
- Old demo dataset moved to `data/generated.old-demo-backup/`. Fresh
  publish is `MSRTC · 309 trips · 3 division files · containsDemoData:
  false`.
- Reference data updated: added the `amravati` division, the
  `kondhali` / `amravati` / `mumbai` depots, and matching stops. Extended
  the service-type aliases with Marathi labels visible in the PDFs
  (`साधी` / `सेमी` / `हिरकणी` / `शिवशाही` / `शिवनेरी` / `आसनी शयनयान` /
  `ई-बस`).

### OCR pipeline (ready for the remaining ~150 pages)
- `scraper/ocr/ocr-pdfs.py` + `README.md` — a proper Python + tesseract
  script that renders each scanned page at 300 dpi and writes
  `data/ocr/<slug>-p<NN>.{txt,tsv}`. Refuses to run without a Marathi
  language pack — we never publish OCR guesses.
- One-time user setup: install Tesseract 5 with the `mar` language
  pack (link + steps in the README), then `py -m pip install PyMuPDF
  pillow pytesseract`, then `py scraper/ocr/ocr-pdfs.py`. All
  remaining PDF pages will land as `data/msrtc/source/ocr/*.json`
  and flow through the same pipeline.

### UI — multicolor, per-division, next-departure aware

- **Tailwind palette (`tailwind.config.js`)** now carries the full MSRTC
  service livery — Ordinary red / Semi orange / Hirkani pink /
  Shivshahi violet / Shivneri royal-blue / Aasani-Shayanyaan indigo /
  Sadhi-Shayanyaan teal / E-Shivai emerald / Yashwanti amber —
  matching the 5-colour flag legend printed on the PDFs. Also a
  `svc*Bg/Fg/Ring/solid` token per role.
- **`ServiceBadge` / `BusCard`** now pick their chip and stripe colour
  from that palette via a shared `serviceRole()` helper. Result: every
  bus card and every chip has the same livery as the printed
  timetable.
- **`DivisionsGrid` + `ServiceLegend` components + HomePage section**
  — a colourful, one-per-division grid (icon + city-name + trip-count
  + coloured underline stripe) with a green “✓ 2025 verified” pill on
  the divisions that already have PDF-transcribed data. Followed by
  the MSRTC bus-livery legend so people already used to the printed
  timetable feel at home.
- **`NextDeparturesCard` on the home page** — an always-visible
  live-updating list of the next 5 upcoming departures anywhere in the
  loaded dataset (30-second tick, red pulse when ≤ 30 min away), with
  the correct service-livery chip on each row and a direct link into
  the corresponding route page. No location permission needed; works
  offline.

### Smart notifications
- Extended `services/notifications.ts` with the missing bits:
    - `DepartureAlert` records (route + service + `HH:MM` + N-min lead
      time), stored in IndexedDB via existing kv helpers.
    - `addDepartureAlert` / `removeDepartureAlert` /
      `getDepartureAlerts` for the future settings row.
    - `scheduleAlerts()` — replays every stored alert into
      `setTimeout` handlers so the browser fires a `Notification` N
      minutes before the next daily occurrence and auto-reschedules
      for the next day when it triggers. All idempotent (safe to
      re-run on tab focus / after data reload).
    - Kept the existing change-set notifier (route-timetable-changed)
      intact.

### Fixes along the way
- `scraper/util/fs.ts`: `copyDir` now refuses to recurse into a
  `.backup` subtree (the source of the nested `.backup/.backup/…`
  explosion after an interrupted Windows write); `rmrf` retries on
  spurious Windows `ENOTEMPTY`.
- Manual cleanup of the pre-existing infinitely-nested
  `data/generated/.backup` tree via a small helper in
  `scratchpad/purge.py` (walks with `\\?\` long-path prefix).

## What is honestly *not* delivered

- **The other ~150 PDF pages.** Every page is a scanned image, so
  they need OCR. Rather than hand-transcribing (error prone) or
  faking data, I set up the OCR pipeline and left it as a one-command
  step you can run once Tesseract with the Marathi pack is installed.
- **Real bus photographs.** The scanned PDFs contain marketing photos
  of MSRTC coaches, and the MSRTC portal has more, but those images
  are the operator’s intellectual property — pulling them into the
  app without a licence would misrepresent the app as official
  content, which the disclaimer explicitly rules out. The existing
  self-authored SVG bus illustrations under `public/buses/*.svg` are
  kept.
- **Auto-scraping the MSRTC portal** at scale. `MsrtcOfficialSource`
  remains a guarded scaffold — the live booking portal must not be
  used to harvest bulk timetables. The `msrtc-pdf` source is the
  legitimate ingestion path for the divisional PDFs.

## How to run locally

```
npm run scrape         # msrtc-pdf source by default → 309 trips
npm run validate
npm run generate       # writes data/generated
npm run sync-data      # copies to public/data
npm run build
npx vite preview       # local preview
```
